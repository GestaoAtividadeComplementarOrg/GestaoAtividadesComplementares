Introdução
==========

Esta seção documenta o processo de desenvolvimento adotado pelo projeto.

Seu objetivo é estabelecer um conjunto de práticas que garantam organização,
padronização, rastreabilidade e qualidade durante todo o ciclo de vida do
software.

A documentação aqui descrita complementa a arquitetura do sistema,
definindo como a equipe trabalha de forma colaborativa utilizando GitHub.


Objetivos
=========

A governança do desenvolvimento busca:

* padronizar o fluxo de trabalho;
* reduzir conflitos entre desenvolvedores;
* facilitar revisões de código;
* melhorar a rastreabilidade das alterações;
* manter histórico consistente;
* garantir previsibilidade durante o desenvolvimento.


Escopo
======

Esta seção descreve:

* fluxo de branches;
* convenção de commits;
* organização das Issues;
* organização das Sub-Issues;
* Pull Requests;
* revisão de código;
* labels;
* milestones;
* versionamento;
* estrutura do GitHub;
* critérios de conclusão das tarefas.


Princípios
==========

As práticas adotadas seguem os seguintes princípios.

Simplicidade
------------

Os processos devem ser simples o suficiente para não prejudicar a velocidade de
desenvolvimento.

Padronização
------------

Todas as alterações devem seguir os mesmos padrões.

Colaboração
-----------

O desenvolvimento é realizado coletivamente.

Rastreabilidade
---------------

Toda alteração deve possuir origem identificável.

Qualidade
---------

Nenhuma funcionalidade deve ser integrada sem revisão.

Relacionamento com a Arquitetura
================================

A governança complementa a arquitetura do sistema.

Enquanto a arquitetura define como o software será construído, a governança
define como os desenvolvedores irão construí-lo.


Resumo
======

A governança do desenvolvimento estabelece as regras de colaboração da equipe,
buscando garantir qualidade, organização e evolução consistente do projeto.
